## Implementation corrections

The executable plan samples were reconciled with the actual repository exports, JSON posting-policy shape, credit-note constraints and PostgreSQL behavior. One shared canonical serializer serves tax returns and e-invoicing. Tax facts retain signs and base-currency twins, and no money passes through binary floats. Document inputs accept `taxCodeId` and `taxInclusive`; client-supplied `taxAmount` and `totalInclTax` are rejected because the server computes them. Both figures remain available in responses.

Company guards cover ID-based reads and mutations, including sibling companies of the same tenant. Credit notes retain `tax_inclusive`; historical correction refs can resolve archived/expired codes only when their posted source used those codes. New invoices still refuse them. Filing attachments must belong to the return's company.

Remote calls run outside the service's tenant transactions. Successful records and caught faults end their claims, including QR generation and accepted-poll snapshot failures. A stately tax queue lets active polls schedule successors and collapses queued duplicates. Automatic polling checks the twelve-attempt budget before calling, so transient retries and excess deliveries cannot exceed it. Credentials are environment bindings, never database values, and credential echoes are removed before persistence. Diagnostics are returned per call, preventing concurrent submissions from sharing unknown-status metadata. Deadlines cover response-body reads as well as connection/header delivery. Re-recording a transmission preserves its original transmitter; changed company transmitters and profile versions fail before polling or cancellation contacts a different remote contract.

The tax-return runbook records periodic filing separately from document e-invoicing; the frozen tax job submits documents. PostgreSQL JSONB idempotency replay preserves the response value/status and may reorder object keys; canonical return payloads are stored as strings and preserve bytes.

The public-protocol completion pass adds OAuth acquisition/reuse/expiry, exact-byte submission hashing and envelope encoding, matching submission receipts, durable submission/document identifiers, cancellation encoding and validation links. The statutory legal mapper and signer remain explicit required dependencies. Polling a remotely cancelled document records its required timestamp. Refused/unconfirmed cancellation retains the accepted state and QR link, records the diagnostic and releases its claim. Authentication-refused poll bodies cannot produce acceptance, and error outcomes retain their diagnostic. The sandbox profile draft is review data outside deployed profiles; application registration remains disabled.

It lists and filters returns, pages the return list, discovers regime/version choices across all tax-code pages, creates drafts, and opens selected returns. ## PR 11 review remediation — 2026-10-07

A code review of PR 11 (2026-10-06) found four merge blockers. Each was fixed test-first on the PR branch, its new tests shown to fail on the unfixed source, and each fix adversarially reviewed. An integrated re-review of all four then confirmed thirteen findings, ten distinct: six code defects in or exposed by the fixes were fixed the same way, two documentation gaps were closed, and two defects that predate the fixes are recorded rather than fixed. The rules that touch money semantics, security or the data model are proposed amendments to ADR 0050 (tax) and ADR 0053 (e-invoice state) and are listed as Plan Contracts' "PR 11 review" rows; none is ratified by landing.

| Blocker | Defect | Fix |
|---|---|---|
| B1 | A partial credit note pro-rated net, tax and gross independently, so on a taxed line the credited total missed amount + tax by 0.0001 about one time in five on a one-third credit and the note could not post. | `creditNoteFrom` pro-rates net and gross and derives tax as gross − net (ADR 0050 decision 8). |
| B2 | A poll that failed or met an unmapped label demoted a `submitted` transmission to resubmittable `error`, so the authority could receive the document twice; past the poll limit no verb could reach the row. | A poll never demotes; a 2xx submit that names an external id is `submitted`; a 2xx the log cannot address carries a warning and is terminal for automation; `POST …/einvoice-transmissions/{id}/poll` is the operator's reconciliation; the services bind the company inside the claim (ADR 0053 amendment). |
| B3 | Converted invoices could never carry tax: the conversion wrote no tax code and never ran the persist-time computation, and replacing the lines cascaded the fulfilment links away. | `taxCodeId` at body and line level with a `null` opt-out, inheritance from the source line, `computeDocumentTax` at conversion, refusal of coded lines from inclusive sources, 3D carrying the order's tax facts, and a guard on replacing a derived draft's lines (ADR 0050 decisions 1–6). |
| B4 | The staging image crashed at boot: the runtime stage lacked `packages/db/einvoice-profiles` (and, since before Phase 5, the domain JSON schemas) and the transmitter registry threw at module load. | The image copies every file the module graph reads outside `src`, `playwright` is an `apps/api` runtime dependency, and `registerDefaultTransmitters` fails closed with a logged skip report; proven against a real image build (the unfixed image cannot load `@dulja/db`; the fixed one reaches the database connection). |

Integrated re-review follow-ups fixed: a percent-encoded path (`…/%70oll`) bypassed `SELF_TRANSACTED` and reopened the pool deadlock — both route lists and the idempotency fingerprint now match the routed path; a second queued submit job could resend a warned row — the claim refuses it and only the operator's submit re-admits it, which also refuses while a call is in flight and exposes `claimedAt`; a poll job that found e-invoicing disabled stopped silently — it now leaves a marker naming the operator route; B1's derivation trusted any earlier credit — a credit is now refused over a `returns` claim it cannot trust (ADR 0050 decision 9); 3C's link price copy could carry an inclusive order's gross price into a taxed conversion — it now refuses a `tax_inclusive` mismatch and carries the order line's code (decision 7); and the line-replacement guard froze client-drafted purchase returns — it now applies to conversions and service-derived credit notes only. The documentation gaps: B1's rule had no ADR record, and Plan Contracts lacked rows for the B3 and B4 changes; both are now recorded. Two defects that predate the fixes were first recorded here and are fixed in the third round below: 3D's FEFO splits copying the whole order-line discount, and a profile version bump stranding transmissions recorded under the old version.

| Area | Defect | Fix |
|---|---|---|
| Tax returns | Overlapping ranges (Jan–Mar beside Feb–Apr) were accepted and reported the same facts twice. | `createTaxReturn` refuses a range sharing a day with another return of the company and regime, 409, naming it (decision 15). |
| Tax returns | A taxed document dated in a filed return's range posted facts no return would report; a stale generated return could be filed. | `insertTaxTransactions` refuses with `ERR_PERIOD_NOT_OPEN` under a share lock that serialises with filing; `fileTaxReturn` rebuilds and refuses a stale payload (decisions 16–17). |
| Tax returns | An empty period's payload said MYR whatever the company's currency; the tie-out read only 2300/1350; services took ids without the company. | The pack takes the company currency; the tie-out sums the regime's own accounts and tax codes must post to the right account type; every return and code service binds the path company in its own WHERE (decisions 18–19). | E-invoice | A call could outlive the claim window and its record overwrite the claim that took over; a claim read its row unlocked; a second profile version would strand every row of the first. | `timeoutMs` capped at 60 s (half the window, pinned by a test); records end only their own claim; the claim reads the row `for no key update`; every shipped profile version is registered and poll/cancel use the row's pinned version (ADR 0053, 2026-10-07). |

| Posting | Two `each_tax` rules planned one tax group twice: the post failed on `tax_transaction`'s key or the return double-counted. | Tax lines are planned once per document over the union of matched lines (decision 13). |
| Seed | A production seed installed the synthetic 11% regime into a real company. | The seed reads `APP_ENV`; production skips and reports a synthetic regime; every runbook seed command names `APP_ENV` (decision 14). |
| 3D | FEFO splits and partial deliveries each carried the order line's whole discount, under-billing (and since Phase 5 under-taxing) the invoice. | The discount is shared pro rata with the completing line taking the residue, capped, and an out-of-bound client history is refused (decisions 10–12). |
